# 玩具厂计件计数与工资结算（Android 管理员版）

车间统计员一个人用的**单机记账 App**：记件数、算工资、锁账、发工资条。
**离线优先**——记账、查询、结算全程不联网；云端备份只是可选的异地留档。

- 技术栈：Flutter 3.50 / Dart 3.14，本地 SQLite（`sqflite`）
- 目标平台：Android 7.0+（minSdk 24），单 APK 直接安装
- 金额精度：单价按「万分之一元」整数存储，小计按「分」整数存储，**逐笔四舍五入后累加**
- 测试：244 条自动化测试（核心金额/锁账/逐笔结算/单价隔离/日期归集/节假日/查找分页/全员下钻/回收站/备份/导入逻辑 + 界面冒烟与超大字号排版）

## 三、关键设计决策

### 1. 金额为什么全用整数

浮点数 `0.035 * 100` 可能得到 `3.4999999999999996`，四舍五入到分就会出错。
本项目：

- 单价存 `unit_price_ten_thousandth`（0.035 元 → `350`）
- 小计存 `subtotal_cents`（元 × 100 的整数）
- 每笔 `round(quantity × price / 100)`，**先取整到分再累加**，报表脚注「逐笔取整后合计」

### 2. 快照优先，改档案不影响历史

`piece_records` 存 `worker_name_snapshot / toy_name_snapshot / process_snapshot /
unit_price_snapshot`。档案改名、调价、停用都不会改写任何历史单据。

改数量时沿用**原单价快照**重算；只改备注则金额完全不动。

### 3. 分组键含单价，杜绝「平均单价」

结算按 `(worker_id, toy_id, process_snapshot, unit_price_snapshot)` 分组。
同一工序中途调价（0.20 做 100 件 + 0.25 做 100 件）必然拆成两行，合计 45.00。

### 4. 防重复提交落在数据库层

保存前先生成 UUID 作为主键，插入时用 `ConflictAlgorithm.ignore`；
双击只会落一行，第二次插入返回已存在的记录。

### 5. 锁账只有一个闸门

所有写操作（新增/修改/删除/回收站恢复）统一走
`MonthLockGuard.assertEditable / assertRangeEditable`。
改日期跨月时**同时校验原月份与目标月份**。

### 6. 只有调整项的工人也要出现

结算先用 SQL 分别聚合计件与调整项，再在 Dart 里按 `worker_id` 合并，
因此「只领补贴、没有计件」的人不会从结算清单里漏掉。

### 7. 工资条用 Canvas 画，不用截图

1080px 宽的工资条逐页 `Picture.toImage` 生成 PNG，每页按行数均分（每页 ≤18 行）。
一张几百行的工资条整体截图会 OOM，分页渲染把内存占用压成常数。

### 8. 结算状态按月记，锁账与结算解耦

`settlement_marks(worker_id, month, is_settled)` 只存状态，不复制金额：

- 金额永远由计件 + 调整项现算，补录、调价后不会出现「标记里的数字对不上账」；
- 结算页按 `substr(date,1,7)` 把金额按月拆开，才能算清「已结算多少 / 未结算多少」；
- 锁账管「能不能改」，结算管「钱发没发」，可以先结算后锁账，也可以只结算不锁账；
- 判定只看**有账的月份**，跨月区间里没干活的月份不会把状态卡成「部分已结」。

### 9. 单价：档案价是「默认值」，流水价是「事实」

两个单价字段职责不能混：

| 位置 | 字段 | 谁能改 | 影响范围 |
| --- | --- | --- | --- |
| 玩具工序档案 | `toys.unit_price_ten_thousandth` | **只有**「设置 → 玩具工序」 | 以后新录入的默认价 |
| 每一条流水 | `piece_records.unit_price_snapshot` | 录入时填的临时价 | 只这一笔 |

计数页的「临时调价」只写后者，**绝不回写档案**（`test/temp_price_test.dart` 钉死这条）。
两者不一致时列表自动打紫色「临时调价」角标，提示"别拿它跟当前档案价比"。

顺带修掉一个真实故障：`Toy.priceLabel` 早先自带「 元」，
被直接回填进「本次单价」输入框后解析必然失败，于是改单价会莫名其妙地
提示"数量要大于 0 / 单价格式不对"。现在 `priceLabel` 是纯数字，
单位由展示层在需要的地方单独给。

### 10. 结算：整月快捷 + 逐笔精确

每条流水和调整项都有 `settled_at`：

* `NULL` = 跟随「人 + 月」的整月标记（老版本行为，升级后一笔都不变）；
* 非空 = 这一笔已单独结算。

判定取并集，金额逐笔累加，所以恒等式 `已结算 + 未结算 == 应付` 在任何组合下都成立。
状态按**笔数**判（不是金额），避免"都结清了但净额为负"被判成未结算。

只有两态怎么表达"整月已结、这一笔例外"？答案是**展开**：
取消某一笔时若所在月有整月标记，先把整月标记落到每一笔，再清掉整月标记，
最后把这笔置空 —— 等价结果，且不需要第三态（`SettlementEntryRepository`）。

### 11. 业务日期与录入时间彻底分开

一笔账有两个时间，职责不能混：

| 字段 | 含义 | 谁在用 |
| --- | --- | --- |
| `date`（业务日期） | 这活是哪天干的 | **所有**统计、结算、锁账、工资条、CSV |
| `created_at`（录入时间） | 什么时候按的保存键 | 只用于审计展示，从不参与归集 |

今天补录 11 号的活 → 账算 11 号，`created_at` 是今天，
明细里标红「补录 N 天」，点开能看到精确到秒的录入时间。
`test/backfill_test.dart` 把这条不变量钉死：`listByDate('2026-11-11')` 有它，
`listByDate('2026-11-22')` 没有，今日概览也不会把它算进今天。

配套的两个防错：

- 「马上计数」每次进入都把日期重置为今天（`SelectionState.selectTab`），
  否则沿用上次补录的旧日期，第二天照着记就会静默记错日子；
- 从结算页 / 工人详情补录调整项时，默认日期跟随**当前区间**，
  而不是写死今天——否则钱会落到下个月，当期结算看不见。

### 12. 区间口径集中在 `DatePeriods`

周（周一–周日）、自然月、自然季度 Q1–Q4、自然半年、自然年各一条规则，
「这半年」= 当前所在半年，「上半年」= 当年 1–6 月；两者相同时列表里直接写明，
不靠用户猜。结算页只负责展示与查询，口径一处定义。

### 13. 节假日只标注，不参与计算

`CnHolidays` 按年维护放假日与调休补班日（2025–2027，来源为国务院办公厅通知），
`休` / `班` 两种角标用不同颜色区分。查不到年份或日期时返回 `null`，
界面按普通日期渲染——**绝不改变任何金额计算**，也不会因为缺数据而报错。

### 14. 云备份只在前台触发

应用启动/回到前台时检查一次：距上次成功 ≥24 小时**且**本地确有新写入
（`MAX(updated_at)` 晚于上次备份时间）才上传。不用后台定时器——
Android 会杀后台任务，定时器既不可靠又费电。云端只保留最近 30 份**自动**备份，
手动备份永远不会自动清理。

### 15. 查找一套组件，两个页面同一手感

流水页与结算页共用 `SearchField` + `SearchMatchHint`：输入姓名 / 工号 / 拼音首字母
任一命中，命中数与总数一起报（`匹配 4/12 笔`、`3/200 人`），右侧常驻清空按钮，
无匹配时给 `EmptyState` 而不是空白卡片。

工号是**档案表**里的字段，流水只存姓名快照，所以按工号查流水时用
`workerId → code` 的映射补查；工人被停用也照样能查到历史账。
查找只过滤内存里已加载的列表，**不改任何统计口径**（汇总卡始终按全员算）。

### 16. 分页口径收在一处

`Pager`（`domain/rules/pager.dart`）只做纯计算：页数、当前页边界、切片、
换档位后回第 1 页。0 条数据时页数为 1 而不是 0，所以不会出现「第 1/0 页」这种负数下标。

流水列表按 `10 / 20 / 50` 分页，只 build 当前页的行——一天 200 笔时不再一次性
渲染 200 个 Row，滚动与首屏都轻了。换日期、换每页条数、改查找词都会把页码重置。

### 17. 折叠态也要能回答「还差多少钱」

- **应付合计**折叠后保留三个核心口径：合计（含人数）、已结算（金额 + 人数）、
  未结算（金额 + 人数），只收起计件/补贴/计时/扣款/预支与笔数明细；
- **月度锁账**超过 6 个月（半年 / 全年）默认收起，折叠态报「已锁 X 个月 / 未锁 Y 个月」，
  展开后才能逐月锁定/解锁。

折叠只是显示与否，**不动数据、不改口径**：合计 = 已结算 + 未结算 的恒等式在两种状态下都成立。

### 18. 两种视角，一套结算动作

- **按工人结算**：从人找账，看某个人的完整账单（区间应付、逐笔明细、工资条）；
- **点汇总项下钻**：从维度找人。点「未结算 / 已结算」按状态横切全员，点
  「计件 / 补贴 / 计时 / 扣款 / 预支」按项目横切全员。

下钻名单里可以直接操作，且与主页面同一套口径：

- 未结算名单里「结清本期」走 `SettlementEntryRepository.markRange`，只改状态不动金额；
- 计价项名单里可以逐笔「结算 / 取消」，也可以对某个工人的这一类「全部结清」
  （只动这一项，不波及其它账）；
- 每次操作后重算聚合并 `notifyDataChanged`，弹层与背后的汇总卡同时刷新，
  关掉弹层不需要再手动刷新。

## 五、数据与隐私

- 全部数据在手机本地 SQLite，不上传、不埋点、不采集设备信息；
- WebDAV 账号与应用密码存在系统安全存储（Android Keystore 加密），
  不写进账本与备份文件；
- 备份 JSON 是**明文**，包含工人的姓名、电话、身份证号与工资，请自行保管好备份文件。
