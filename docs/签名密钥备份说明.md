> 这份文档和 `.jks` 文件同等重要。**丢了密钥 = 以后无法覆盖升级**，
> 请把本文与密钥文件一起离线保存（U 盘 / 加密网盘 / 打印一份放抽屉）。
>
> ⚠️ **本文档会进 git 仓库，所以真实密码不写在这里**（已用占位符代替）。
> 带真实密码的完整版在你的本地 `dist/签名密钥备份说明.md`，该目录已被 `.gitignore` 排除。
> 请自行另存一份到密码管理器或纸上，**不要**把密码填回本文件再提交。

```properties
keyAlias=toy-piecework
storeFile=toy-piecework-release.jks
```

## 二、为什么要留着它

Android 只允许**同一个包名 + 同一个签名**的 APK 覆盖安装。
换了签名再安装，系统会报「应用未安装」或「签名冲突」，只能先卸载——
而卸载会**清空应用数据**（整本账）。

所以：

- 有密钥 → 以后每个版本都能覆盖升级，账本数据完好；
- 没密钥 → 只能卸载重装，必须先手动备份账本再恢复，且旧版本无法回退。

## 三、怎么备份（建议做三份）

1. **U 盘 / 移动硬盘**：拷 `toy-piecework-release.jks` 和本文档；
2. **加密网盘**：打包成 zip 并加密码（例如 7z 加密），再上传；
3. **纸质记录**：把上一节的密码抄在纸上，和厂里的重要合同放一起。

> 密码与文件**不要放在同一处明文**（例如把密码写在文件名里），否则一起泄露。

---

## 四、换电脑后怎么继续出包

1. 装好 Flutter SDK 与 Android SDK；
2. 把 `toy-piecework-release.jks` 放回 `android/app/` 目录；
3. 在 `android/` 下新建 `key.properties`，内容按上面第一节填写；
4. 构建：

```bash
flutter build apk --release
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`。

若 `key.properties` 不存在，构建脚本会自动退回 debug 签名（能出包，但**不能**用于覆盖正式版升级）。

## 五、校验当前 APK 的签名

```bash
# 用 Android SDK 自带的 apksigner
$ANDROID_HOME/build-tools/<版本>/apksigner verify --print-certs app-release.apk
```

输出中的 `SHA-256 digest` 应与上表一致，说明用的是同一把钥匙。

手机上也可以用「应用信息 → 版本」查看包名，或安装 `APK 签名校验` 类工具比对。

## 六、常见问题

**Q：我把密码忘了，还能用这个 jks 吗？**
不能。PKCS12 的密码无法绕过，只能重新生成密钥——意味着必须卸载重装。

**Q：能改成别的密码吗？**
可以，但要同时改 `key.properties`：

```bash
keytool -storepasswd -keystore toy-piecework-release.jks -alias toy-piecework
```

改完记得同步更新本文档。

**Q：能上架应用商店吗？**
本包定位是厂内自用，未做隐私政策与商店合规材料，建议直接传 APK 安装。

**Q：`app-release.apk` 为什么有 60MB？**
这是通用包，内含 arm64 / armv7 / x86_64 三套 Flutter 引擎（每套约 20MB）。
若只想减小体积，可以按 ABI 拆分：

```bash
flutter build apk --release --split-per-abi
# 多数手机装 app-arm64-v8a-release.apk 即可（约 20MB）
```
